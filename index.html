Claude Code на VPS, ноутбук только подключается

Сервер в США, SSH и tmux. Anthropic видит IP сервера, сессия живёт после закрытия ноутбука, Remote Desktop не нужен.

Начать Скачать PDF

Ubuntu 24.04 · 20-30 минут · Claude Pro, Max или Team · SSH, tmux и установка проверены на Ubuntu 24.04

Зачем так

Не потому что модно, а потому что это снимает три боли сразу.

1

IP сервера, не ноутбука

Claude Code отправляет запросы к Anthropic с VPS. VPN ноутбука остаётся на плече SSH. Провайдер и сайты видят сервер, а не твой домашний IP.

2

Сессия не умирает

tmux держит Claude на сервере, даже если ноутбук уснул, Wi-Fi пропал или ты закрыл терминал. Вернулся одной командой и продолжил.

3

Меньше поверхности

Только SSH, без RDP и открытых портов. Сервер закрыт ключом, firewall и fail2ban. Это проще проверить и сложнее сломать.

Пошагово

Иди сверху вниз. Команды можно копировать кнопкой. Если что-то не сходится, сначала загляни в раздел «Ошибки», потом пиши в чат потока.

01

SSH и отдельный пользователь

Тебе нужен VPS с Ubuntu 24.04, 4 ГБ памяти и root-доступом. IP и пароль root даёт провайдер в письме или панели. Сначала зайди на сервер с ноутбука.

Если SSH-ключа на ноутбуке ещё нет, создай его. Если ключ есть, команда ls покажет файл, и ssh-keygen не запустится.

ls ~/.ssh/id_ed25519.pub || ssh-keygen -t ed25519 -C "vps-guide"

Положи ключ на сервер. Если вход по паролю ещё разрешён, проще всего через ssh-copy-id.

ssh-copy-id root@203.0.113.10
ssh root@203.0.113.10

Вместо 203.0.113.10 подставь IP своего сервера. Если ssh-copy-id нет, добавь содержимое ~/.ssh/id_ed25519.pub в /root/.ssh/authorized_keys на сервере. На Windows те же команды в PowerShell, только путь к ключу будет $env:USERPROFILE\.ssh\id_ed25519.pub.

Дальше создай отдельного пользователя. Под root работать не надо: агент не должен иметь права менять всю машину.

adduser dev
usermod -aG sudo dev
install -d -m 700 -o dev -g dev /home/dev/.ssh
cp /root/.ssh/authorized_keys /home/dev/.ssh/authorized_keys
chown dev:dev /home/dev/.ssh/authorized_keys
chmod 600 /home/dev/.ssh/authorized_keys
Зачем dev в sudo: так проще ставить обновления. Если хочешь строже, после установки убери его из sudo командой sudo deluser dev sudo. Агенту не давай root-пароль без нужды.
Проверь до того, как закроешь root: открой второе окно терминала на ноутбуке и зайди как dev. Если пускает, root можно закрывать.
ssh dev@203.0.113.10
02

Поставь минимум программ

На чистой Ubuntu нужны tmux, git, curl, firewall и fail2ban. Всё ставится одной командой.

sudo apt update
sudo apt install -y tmux git curl ufw fail2ban

Проверь, что tmux на месте. Версия должна быть 3.x.

tmux -V
Если sudo просит пароль, это пароль пользователя dev, который ты задал в шаге 01.
03

Закрой сервер

Открытым должен остаться только SSH. Сначала разреши SSH в firewall, потом включи его. Порядок важен, иначе можно потерять доступ.

sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status

Теперь выключи вход по паролю. Делай это только если во втором окне уже работает ssh dev@IP по ключу. Иначе останешься без доступа. На облачных серверах настройки часто лежат в отдельном файле, поэтому пишем свой, с именем 00-, чтобы он читался первым.

echo 'PasswordAuthentication no' | sudo tee /etc/ssh/sshd_config.d/00-no-password.conf
sudo sshd -t && sudo systemctl reload ssh
sudo sshd -T | grep -E 'passwordauthentication|permitrootlogin'

Включи fail2ban. Он будет банить IP, которые перебирают SSH.

sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd
Если jail sshd не найден, создай его вручную и перезапусти fail2ban.
printf '[sshd]\nenabled = true\n' | sudo tee /etc/fail2ban/jail.d/sshd.local
sudo systemctl restart fail2ban
sudo fail2ban-client status sshd
Не включай RDP. Порты 3389 и VNC наружу не нужны. Если очень нужен GUI, сначала прочитай раздел «Ошибки», там про туннель.
04

Поставь Claude Code

Официальный установщик ставит Claude Code в домашнюю папку пользователя, без root.

curl -fsSL https://claude.ai/install.sh | bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
claude --version

Если команда claude не находится, проверь путь и перезайди в SSH.

echo $PATH
ls -la ~/.local/bin/claude
Версия на момент проверки: Claude Code 2.1.x. Если установщик просит Node.js, значит у тебя старая инструкция, нативный установщик Node не требует.
05

Войди в аккаунт

На сервере нет браузера, поэтому Claude Code покажет ссылку. Открой её на ноутбуке, войди в свой аккаунт и вставь код обратно в терминал.

claude

Выбери Claude account with subscription. Дальше: скопируй ссылку, открой в браузере, подтверди доступ, скопируй код, вставь в терминал.

Это единственный запрос к claude.ai с ноутбука. Дальше рабочие запросы Claude Code идут с сервера. Так и задумано.

Проверь вход командой /status внутри Claude или отдельно:

claude doctor
Не вставляй пароль или API-ключ в чат потока. Если используешь API-ключ, заведи его через read -s, а не в истории команд. Для Remote Control API-ключ не подходит, нужен аккаунт с подпиской.
06

Запусти в tmux

tmux это слой, который держит терминал на сервере. Без него Claude умрёт вместе с SSH.

tmux new -s agent
mkdir -p ~/project
cd ~/project
claude

Отцепиться от сессии: нажми Ctrl+B, отпусти и нажми D. Claude продолжит работать.

Вернуться с ноутбука одной командой:

ssh -t dev@203.0.113.10 tmux new -A -s agent

Чтобы не вспоминать IP, добавь короткий псевдоним на ноутбуке. Для zsh это ~/.zshrc, для bash ~/.bashrc.

echo "alias agent='ssh -t dev@203.0.113.10 tmux new -A -s agent'" >> ~/.zshrc
source ~/.zshrc
agent
Флаг -A значит «подключись к существующей сессии или создай новую». Одна команда на все случаи.
07

Проверь обрыв связи

Это главный тест. Попроси Claude что-нибудь сделать, дождись ответа, закрой окно терминала целиком, не отцепляйся. Потом вернись командой agent.

  • 1Сессия tmux на месте, Claude не перезапускался.
  • 2История разговора видна, можно продолжать с того же места.
  • 3Если Claude всё-таки умер, в папке проекта работает claude -c и поднимает последний разговор.

Если сервер перезагрузился, tmux исчезнет. Это нормально: файлы и история Claude остаются, сессию поднимаешь заново через claude -c.

08

VS Code Remote-SSH, если нужен редактор

Можно работать не в терминале, а в VS Code. Важно: расширение Claude Code должно стоять на сервере, а не на ноутбуке.

  1. 1Поставь расширение Remote - SSH.
  2. 2Command Palette: Remote-SSH: Connect to Host, введи dev@203.0.113.10, открой папку проекта.
  3. 3В удалённом окне установи расширение Claude Code. Оно встанет на сервер.
  4. 4Войди в аккаунт. Если панель крутится, в терминале на сервере запусти claude auth login и вставь код.
Долгую работу всё равно держи в tmux. Сессия, запущенная из расширения, живёт вместе с extension host. Закрыл окно надолго, процесс может умереть. tmux надёжнее.
09

Телефон через Happy, если нужно

Happy это сторонний open-source клиент. Он ставится на сервер, а телефон подключается к нему через relay. Модель по-прежнему работает с сервера.

node -v
npm config set prefix ~/.npm-global
echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
npm i -g happy
happy claude

Дальше поставь приложение Happy на iPhone или Android и отсканируй QR. Если node -v показывает версию ниже 20, сначала поставь Node.js 20 или новее.

Это не обязательно для основного пути. Если телефон не нужен, шаг можно пропустить. Relay сторонний, трафик шифруется, но это дополнительный слой доверия.

Пусть агент сделает сам

Если не хочешь вводить команды руками, дай своему агенту этот промпт. Он сначала покажет план, потом сделает. Пароль и токен в чат не передавай.

Агент получит доступ к серверу. Прочитай его план до «ок». Если сервер общий или на нём живут чужие сервисы, не давай агенту root и не разрешай менять ufw без отдельного тестового сервера.
Ты помогаешь мне поднять Claude Code на моём VPS и работать с ноутбука по SSH.
Цель: Claude Code крутится на сервере, я подключаюсь из терминала ноутбука, сессия живёт в tmux, Anthropic видит IP сервера.

Мои данные:
- IP сервера: [IP]
- Вход: root или [пользователь]
- SSH-ключ: [путь к ключу, если есть]
- Новый пользователь: dev
- ОС: Ubuntu 24.04

Работай так:
1. Сначала только чтение. Покажи uname -a, /etc/os-release, free -h, df -h /, getent passwd, ss -tlnp, sshd -T, ufw status, systemctl list-units --type=service --state=running.
2. Если на сервере есть чужие сервисы, пользователи или ufw уже активен, остановись и спроси меня. Не трогай nginx, docker, базы, чужие папки и чужие ключи.
3. Покажи план изменений и жди моего «ок». В плане: пользователь, ключи, пакеты, ufw, fail2ban, установка Claude Code.
4. После «ок» делай по шагам и после каждого шага показывай результат:
   - создай dev, добавь в sudo, положи мой ключ в /home/dev/.ssh/authorized_keys, права 700 на папку и 600 на файл, владелец dev;
   - проверь, что я захожу как dev в отдельном окне, только потом закрывай root;
   - поставь tmux, git, curl, ufw, fail2ban;
   - разреши OpenSSH в ufw и включи его;
   - выключи PasswordAuthentication только после проверки входа по ключу, через /etc/ssh/sshd_config.d/00-no-password.conf, сделай backup sshd_config и проверь sshd -t перед reload;
   - включи fail2ban и покажи fail2ban-client status sshd;
   - установи Claude Code от имени dev через официальный установщик, добавь ~/.local/bin в PATH, покажи claude --version.
5. Не запускай claude login за меня, не проси пароль или токен в чате. В конце дай точную команду, которой я сам войду в аккаунт, и что я должен увидеть.
6. Проверь: whoami, hostname, curl -s https://ifconfig.me, ss -tlnp, ufw status, tmux -V, claude --version. Покажи вывод.
7. Дай отчёт: что изменено, что проверено, как откатить. Откат: удалить пользователя dev, вернуть sshd_config из backup, выключить ufw, если он был выключен.
8. Никаких RDP, VNC, открытых 3389, секретов в git и логах.

Если данных не хватает, задай вопрос и остановись. Не угадывай.

claude --version

Чек-лист безопасности

  • ✓Отдельный пользователь dev, не root.
  • ✓SSH только по ключу, вход по паролю выключен.
  • ✓Firewall разрешает только 22.
  • ✓fail2ban следит за SSH.
  • ✓Нет RDP, VNC и открытых портов 3389/5900.
  • ✓Секреты не в git, не в истории команд, не в чате.
  • ✓Обновления ставятся регулярно: sudo apt update && sudo apt upgrade.
  • ✓Токены и ключи можно отозвать, доступ закрывается одним userdel.

Если сломалось

Permission denied (publickey)
Ключ не попал в ~/.ssh/authorized_keys пользователя dev, не тот пользователь или сбиты права. Проверь на сервере: ls -la /home/dev/.ssh, папка 700, файл 600, владелец dev. Зайди через root и поправь.
Connection refused или timeout
Сервер выключен, сменился IP или провайдер закрыл 22. Проверь панель провайдера и консоль. Если включил ufw и потерял доступ, зайди через консоль провайдера и выполни ufw allow OpenSSH.
claude: command not found
Не подхватился PATH. Выполни source ~/.bashrc или перезайди. Проверь ls ~/.local/bin/claude. Если файла нет, повтори установщик.
Login expired
Сессия входа истекла. Внутри Claude выполни /login и пройди вход заново. Для долгой работы без браузера можно выпустить токен через claude setup-token на машине с браузером.
tmux: no sessions
Сервер перезагрузился или сессия умерла. Зайди в папку проекта и выполни claude -c. История разговора и файлы на месте.
Remote Control requires a subscription
Remote Control не работает с API-ключом и со своим ANTHROPIC_BASE_URL. Нужен вход через аккаунт Claude с подпиской Pro, Max, Team или Enterprise.
Мало места на диске
Проверь df -h. Почисти кэш npm: npm cache clean --force. Удали старые логи и ненужные папки. Claude Code сам по себе занимает немного, но проекты и зависимости растут.
Нужен GUI, а SSH мало
RDP наружу не открывай. Если очень нужно, поставь xrdp и слушай только 127.0.0.1, а заходи через SSH-туннель: ssh -L 3390:127.0.0.1:3389 dev@IP. Либо используй VS Code Remote-SSH, этого хватает в большинстве задач.

Чего эта схема не делает

Не меняет регион

Anthropic считает физическое нахождение, а не IP. VPS в США не делает неподдерживаемый регион поддерживаемым. Аккаунт могут заблокировать, если правила нарушены.

Не прячет вход

Один раз ссылка входа открывается в браузере ноутбука и идёт на claude.ai. Дальше рабочие запросы идут с сервера.

Не заменяет VPN везде

Если сайты и тесты должны видеть сервер, запускай браузер и тесты тоже на сервере. Claude Code прячет только свои запросы.
